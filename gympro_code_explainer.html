▶ What is a microservice? What did we build?

A microservice is a small, independent application that does one job. Instead of one giant app, GymPro is split into 9 separate Spring Boot apps that talk to each other.

eureka-serverService Registry — every service registers here so they can find each other by name
gateway-serviceFront door — every Postman request comes here first. Checks JWT, then routes to the right service
auth-serviceLogin / Register — creates users, checks passwords, issues JWT tokens
member-serviceMember profiles — CRUD for gym members
trainer-serviceTrainer profiles + schedules — who is available when
plan-serviceMembership plans — monthly/quarterly/yearly + subscribe
booking-serviceBook sessions — member books a trainer slot. Uses Feign to call notification-service
notification-serviceEmail sender — sends Gmail SMTP emails. Called by booking via Feign
payment-servicePayments — dummy payment flow (UPI/card/QR)
▶ What happens when Postman hits POST /members?
1. Postman sends POST http://localhost:8080/members with Bearer token in header
↓
2. gateway-service (8080) receives it — JwtAuthFilter runs
↓
3. Gateway reads the JWT, extracts email + role, adds X-User-Email and X-User-Role headers
↓
4. Gateway looks at routing rules — /members/** → routes to member-service (lb://member-service)
↓
5. member-service (8082) MemberController.create() runs → MemberService.createMember() → saves to MySQL gympro_member
↓
6. Response flows back: member-service → gateway → Postman

JwtUtil.java — token generator
▶How JWT token is built

A JWT has 3 parts separated by dots: Header.Payload.Signature

@Value("${jwt.secret}")Reads jwt.secret from application.properties. That 256-bit key is used to sign the token
.setSubject(email)Puts email in the Payload — this identifies who the token belongs to
.claim("role", role)Adds role to Payload — gateway reads this to know if user is ADMIN/MEMBER/TRAINER
.setExpiration()Token expires after 24 hours — after that it's invalid
.signWith(getKey())Signs with HMAC-SHA256 — only our server can create valid tokens
SecurityConfig.java
▶Why we have SecurityConfig in auth-service (different from others)

auth-service is special — it needs BCryptPasswordEncoder as a Bean. Other services just disable Spring Security. auth-service allows /auth/** without token (permitAll) and protects everything else.

SessionCreationPolicy .STATELESSNo sessions — Spring won't create HTTP sessions. JWT handles state instead
csrf.disable()CSRF protection is not needed for REST APIs — only for browser-based form submissions
gateway-service — port 8080 — NO database
Single entry point. Validates JWT and routes every request to the correct microservice.
application.properties — routing rules
▶How routing works — reading the config
routes[0].predicates Path=/auth/**Any request to /auth/anything gets routed to auth-service
routes[0].uri=lb://auth-servicelb:// means Load Balanced — gateway asks Eureka for the address of "auth-service"
routes[1] Path=/members/**→ member-service. routes[2] /trainers/** → trainer-service. And so on

Eureka knows that auth-service is at 127.0.0.1:8081, member-service at 127.0.0.1:8082 etc. Gateway asks Eureka for the address and forwards the request.

JwtAuthFilter.java — the security guard
▶What this filter does on EVERY request
implements GlobalFilterThis code runs on every single request that comes through the gateway — no exceptions
PUBLIC_URLS list/auth/register, /auth/login, /auth/test don't need a token — allowed through without checking
authHeader.startsWith ("Bearer ")Token must come as: Authorization: Bearer eyJ... — anything else → 401 Unauthorized
authHeader.substring(7)Removes the word "Bearer " (7 characters) to get just the token string
Jwts.parserBuilder()Validates the token's signature using the same secret key — if tampered → exception → 401
claims.get("role")Extracts the role that was embedded when the token was created in auth-service
.header("X-User-Role", role)Adds a new header to the request before forwarding. Downstream services read this to check role
getOrder() return -1-1 means this filter runs before all other filters — highest priority

MemberRepository.java
▶How JpaRepository magic works

By extending JpaRepository<Member, Long> you get these methods for FREE — no SQL needed:

save(member)INSERT or UPDATE — if id is null: INSERT, if id exists: UPDATE
findById(id)SELECT * FROM members WHERE id=? — returns Optional (may or may not have a value)
findAll()SELECT * FROM members — returns all rows as a List
deleteById(id)DELETE FROM members WHERE id=?
findByEmail(email)Custom query — Spring reads the method name and auto-generates: SELECT * FROM members WHERE email=?

Spring Data JPA reads method names and generates SQL automatically. findByEmail → WHERE email=. findByStatus → WHERE status=. No SQL writing needed.

MemberService.java
▶Soft delete — why we don't actually delete

deleteMember() doesn't run DELETE FROM members. Instead it sets status="INACTIVE". This is called a soft delete.

Why? Because if you delete a member row, all their bookings and payments have a missing memberId — the data breaks. Keeping the row with INACTIVE status preserves history.

orElseThrow()If findById() finds nothing (Optional is empty), throw RuntimeException → Spring returns 500 with message
trainer-service — port 8083 — database: gympro_trainer
Trainer profiles + schedule management. Two entities: Trainer and TrainerSchedule.
TrainerSchedule.java — second entity
▶Why there are two entity classes in one service

A trainer can have many schedule slots (MON 9-11, WED 9-11, FRI 2-4). Instead of storing all days in one column (bad), we have a separate table trainer_schedules where each row is one time slot.

trainerId fieldLinks back to the trainer. This is a logical foreign key — no @JoinColumn needed in microservices because each service owns its own DB
available booleantrue = open slot. When booking-service books this slot, it calls PUT /trainers/schedule/{id}/book → sets available=false

▶Why durationDays is set automatically

When ADMIN creates a plan, they just say "MONTHLY" or "YEARLY". The service automatically sets the right number of days:

MONTHLY→ 30 days
QUARTERLY→ 90 days
YEARLY→ 365 days

Admin doesn't need to type 30 or 365 — the service handles it based on durationType string.

booking-service — port 8085 — database: gympro_booking
The most complex service. Uses OpenFeign to call notification-service. Has @EnableFeignClients.
BookingServiceApplication.java
▶Why booking-service has @EnableFeignClients
@EnableFeignClientsTells Spring: scan for @FeignClient interfaces and create HTTP client objects for them automatically

Without this annotation, the NotificationClient interface won't work — you'll get a NoSuchBeanDefinitionException. Only services that call other services need this.

NotificationClient.java — Feign interface
▶What is Feign and why it's powerful

Without Feign, calling another microservice means writing 10+ lines of RestTemplate code. Feign reduces it to just an interface:

@FeignClient (name="notification-service")Spring asks Eureka: "where is notification-service?" Gets the address. Creates an HTTP client. You just call the method
@PostMapping("/notify/send")Feign will call POST http://notification-service/notify/send with the params
@RequestParamEach param becomes a query parameter: /notify/send?email=x&subject=y&message=z

When BookingService calls notificationClient.sendNotification(...) — it looks like a normal Java method call but it's actually making an HTTP request to another microservice!

BookingService.java — createBooking()
▶Why notification is inside try-catch

The booking is saved to DB first, then notification is attempted. The try-catch ensures that if email fails, the booking still succeeds.

repo.save(booking)Booking saved to gympro_booking DB — this MUST succeed
try { notificationClient... }Email attempted — if Gmail is not configured or notification-service is down, this fails silently
catch(Exception e) { sysout }Just prints warning to console — doesn't throw — so caller gets 200 OK even if email failed

This is a good design pattern: don't fail the main operation because a side effect failed.

notification-service — port 8086 — NO database
Receives email requests and sends them via Gmail SMTP. Called by booking-service via Feign.
EmailService.java
▶How Gmail SMTP sending works
JavaMailSenderSpring Boot auto-configures this bean from application.properties — reads Gmail credentials and SMTP settings
SimpleMailMessageCreates a plain-text email object with to, subject, body fields
mailSender.send(message)Connects to smtp.gmail.com:587, authenticates with your Gmail, sends the email
spring.mail.password in propertiesMust be a Gmail App Password (16 chars) — not your real Gmail password. Get it from Google Account → Security → 2FA → App Passwords
application.properties — why no datasource
▶Why this service has no database

Notification-service only sends emails — it doesn't need to store anything. It's a stateless service. No datasource URL, no JPA, no MySQL dependency in pom.xml.

This is exactly why microservices are powerful — each service only has what it needs. No wasted resources.

▶Top 10 reviewer questions — with answers
What is Eureka?Netflix service registry. Every microservice registers its name and IP. Gateway asks Eureka to find service addresses dynamically
What is API Gateway?Single entry point for all client requests. Validates JWT, extracts role, routes to correct service using lb:// (load balanced)
How does JWT work?Login → auth-service creates token with email+role+expiry, signed with secret. Client sends token in every request. Gateway validates signature, extracts role, forwards as X-User-Role header
What is Feign?Declarative HTTP client. You write an interface with @FeignClient — Spring creates the HTTP client automatically. booking-service calls notification-service this way
What is DB-per-service?Each microservice has its own MySQL database. Services don't share tables. Data is linked by IDs (logical FK) not physical foreign keys
What is ddl-auto=update?Hibernate reads entity classes and automatically creates/updates MySQL tables. You don't write CREATE TABLE SQL manually
What is BCrypt?One-way hashing for passwords. "admin123" becomes "$2a$10$...". Cannot be reversed. Login uses encoder.matches() to compare
What is @Autowired?Dependency Injection. Spring finds the matching bean and injects it. You don't write new XxxService(). Spring manages object lifecycle
Why X-User-Role header?Gateway validates JWT once and forwards role to services. Services don't need JWT library — they just read the header. Avoids duplicate validation
What is soft delete?Instead of DELETE FROM table, we set status=INACTIVE. Preserves history — bookings/payments still have valid memberId references
